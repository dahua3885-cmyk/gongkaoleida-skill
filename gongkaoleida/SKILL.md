# 公考雷达公告筛选

## 目标

把广西近三天招聘公告从“发现线索”处理成可直接交给运营判断的稳定清单。重大事实错误必须为0，同一时间窗口和规则版本下结果必须可复现、可对账。

默认只做公告发现、核验、筛选和本地沉淀，不制作视频，不建设网站或工作台。

## 核心工作流

### 1. 固定运行口径

开始前记录：北京时间截止时间、滚动近三天窗口、规则版本、评分版本、上一批次ID、本轮来源和是否完整刷新。

“近三天”以官方原始发布日期为准，不以公考雷达收录时间、搜索引擎时间或转载时间代替。

### 2. 完整发现

用户要求公考雷达完整扫描时，使用已有登录态遍历广西全部相关招聘分类和全部分页，直到列表日期早于窗口。记录每页条数、窗口内原始条数和停止位置。

随后必须按 [references/official-sources.md](references/official-sources.md) 扫描广西人事考试网、自治区人社厅、14个设区市人社/政府招聘入口、广西人才网主站及地市站。每个来源记录入口、栏目、页数、发现数、完成时间和失败原因。

固定官方来源不是“有空再补”的旁路。每轮开始即建立来源覆盖清单，公考雷达与固定官方来源矩阵必须独立执行、统一去重；任一固定入口没有形成`直连完成`或`替代路径完成`记录时，本轮不得标记完成。直连失败必须自行切换HTTP/HTTPS、上级政府栏目、站内搜索、官方域名搜索或人才网主站地市切换，不能因入口报错就跳过该地市。

不得只看标题人数。标题未写人数、学历、编制或报名时间的公告仍进入详情提取队列。同步扫描“资格审查、资格复审、笔试成绩、面试成绩、综合成绩、入围名单、面试名单、体检、考察、拟录用、拟聘用、公示、递补、补录”等名单线索，不能把它们当成无效招聘信息直接丢弃。

公考雷达完整扫描只证明该来源完成，不等于广西全网完成。公考雷达和固定官方来源矩阵均完成时，最多表述为“核心来源完整扫描”；未系统覆盖单位公众号、县区单位站或工作群时仍必须说明来源缺口。

### 3. 批量详情提取

先按公告性质分流为`招录公告`和`招录进度/结果公告`，再批量读取全部窗口内详情。

两类公告共同提取：归属地市、所属区县、单位层级、官方标题、发布主体、官方原文链接、官方发布日期、聚合收录时间和附件证据。

招录公告继续提取：

- 报名开始、报名截止、当前状态；
- 总人数、目标受众实际可报人数；
- 最低学历、专业/资格限制；
- 编制或用工性质原文、待遇原文；
- 单位类别：事业单位综合、教师、医疗、辅警、国企、银行、基层工作者、劳务派遣、见习或其他；
- 待遇证据类型：官方原文、官方未公布或内部参考估算；估算不得冒充公告事实；
- 考试方式：笔试、面试、专业测试、技能测试、体能测试、直接考核或免笔试；
- 笔试科目、面试方式、成绩构成、考试时间地点；
- 考试范围、大纲名称和官方附件链接；
- 公告正文、职位表和附件证据。

名单/进度公告继续提取：阶段类型、涉及人数、资格审查或公示起止时间、面试/体检时间地点、名单附件、关联原招录公告及其稳定ID。对附件计算总行数、有效行数，并识别成绩、排名、学校、专业、学历、岗位、单位和地区等字段。

普通行政进度通知留内部总账；只有通过 [references/list-content-rules.md](references/list-content-rules.md) 硬准入并完成数据复算的记录才进入用户名单素材表。

不要让用户承担“待核验”。字段缺失时继续检查官方页、公众号、职位详情和附件；仍无法确认则只留内部总账，不进入用户清单。

发现线索在内部也必须收敛到终态，禁止把`待核/待确认/待补`当作任务完成状态。每条线索必须依次执行：公考雷达正文 → 官方来源锚点 → 官方站内/官方域名搜索 → 相关职位 → 单岗详情 → Excel/Word/PDF附件 → 公众号正文图片。把`核验是否完成`与`是否具备评分资格`分成两个字段：自核成功写`verified`，全链路仍失败写`evidence_failed`并保持本轮`未完成`；只有通过硬校验的`score_eligible`记录才计算V2分，窗口外、已截止、非社会招聘、受众硬不匹配、官方未发布必填事实或重复线索写明确终态原因并标记`not_scored`。不得把核验动作转交用户，不得宣称任务完成。

详情页超时不等于取证失败。首次超时后把单页超时提高到120—180秒，缩小为4页一批并发，至少重试一次；正文取得后仍必须进入“查看相关职位”和附件。只有上述链路全部执行后才能判断是否无法取证。

考试内容属于展示增强字段，不因官方尚未公布而淘汰一条已满足其他硬条件的公告。公告未说明时写“原文未公布”；只有原文明确写出时才能写“另行通知”。不得依据往年公告、培训机构文章或相似考试自行推定科目。

### 4. 硬校验后评分

先执行硬校验，再按 [references/selection-rules.md](references/selection-rules.md) 评分。硬排除项不打分，不得用`0`作为排序占位；全量审计表统一写`—（未评分）`，并单列终态原因。现有招聘评分属于未完成平台实绩校准的临时先验；同时给出`抖音优先`、`小红书优先`、`双平台`或`暂不制作`的平台建议和依据，不用一个分数同时冒充两个平台的流量预测。

调整权重前按 [references/content-performance-calibration.md](references/content-performance-calibration.md) 收集抖音、小红书公告作品的链接、真实数据和运营盲评。样本未达到要求时，只能新增经验假设，不得宣布最终评分标准已经确定。

运营者直接标注的SS/S/A/B/C另存为`operator_gold`，与`machine_score`分开。它可立即用于校准相同或高度近似公告的选题优先级，但不得当成已验证的平台流量结论。两者冲突时保留差异和原因，不静默改分。

高学历公告可以拆岗位判断：如果博士/硕士岗位占多数，但存在独立、明确且达到人数门槛的本科岗位，只能按本科实际可报人数评分，标题和推荐理由必须明确排除高门槛岗位。

### 5. 稳定增量更新

“重新找、再筛一次、按最新规则更新”默认读取上一版总账并做增量更新，不得清空重建。为新增公告分配稳定ID；原记录即使本轮未再次搜到，也不得无原因消失。

记录新增、升级、降级、淘汰、恢复、事实修正和分数变化。事实和规则未变化时，分数不得漂移。

### 6. 用户输出

默认只交付一个MD文档，文档内输出两张互不混算的总表，格式严格执行 [references/output-contract.md](references/output-contract.md)：

1. `招录公告表`：只展示近三天、当前可报名或报名尚未开始、官方来源可靠、必填字段已核验、达到C级以上的公告；
2. `名单型视频素材表`：展示能从资审、成绩、面试和拟录用/拟聘用名单中提炼学校、成绩、排名、岗位等可验证结论的素材，分为近三天新名单和历史可复用素材。

两张表第一列均为“归属地市”。先分别给出招录公告数量和名单素材数量，再给表格和官方链接。两表均按评分从高到低排列，评分保留数字，等级仅在内部使用，不在用户表拆分S/A/B/C区块或展示等级文字。名单素材不计入“可报名单位数”或“招聘人数”。

交付前必须运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/validate_delivery.ps1 -Path <最终MD绝对路径>`：每张表的表头、分隔行和每条数据行列数完全一致；用户交付文件只有一个；数量总览与两张表实际行数一致；不得把名单候选发现数写成附件完成分析数。Windows PowerShell 5.1 环境不得直接调用 `.ps1`，避免执行策略拦截。校验失败不得交付。

用户要求查看全量评分或内部审计表时，另运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/validate_audit_ledger.ps1 -Path <全量审计MD绝对路径>`：正式评分只允许出现在通过硬校验的记录中；硬排除行必须为`—（未评分）`；禁止`0分`占位；总数必须等于高于等于55分、低于55分和未评分三类之和。

历史仍可报名、过期、硬排除和核验失败只留内部，除非用户追问某条为什么没有入选。

## 必须遵守

- 不把控制数改写成事业编。
- 不把“招满即止”擅自写成具体截止日期。
- 不把公告总人数当作目标受众实际可报人数。
- 不因标题缺人数而排除。
- 不把聚合收录时间当官方发布日期。
- 不把已截止公告、旧公告或待核公告交给用户。
- 不把未进入正式评分的记录写成0分；0不是“硬排除”的同义词，审计表必须写`—（未评分）`并保留原因。
- 不允许以任何形式把`待核/待确认/待补`作为已完成线索的终态；未收敛数量不为0时不得交付或宣布完成。
- 不允许只扫公考雷达；自治区固定来源、14市人社/政府入口和人才网地市层每轮必须逐项留下完成证据。
- 不因直连报错、SSL错误、404、动态页面或第一次超时跳过来源；必须自行走替代入口和多级取证链。
- 不把公考雷达完整扫描表述成广西全网绝对全量。
- 不把往年或同类考试科目推定为本次考试内容。
- 不把“原文未公布”和“另行通知”混写。
- 不把面试资审、成绩、拟录用或拟聘用名单当成新招录公告重复计数。
- 不因它属于资审或拟聘阶段就自动进入素材表；没有可分析字段和可复算结论的普通进度通知只留内部。
- 不在用户表复制姓名、身份证号、手机号、家庭住址、完整准考证号/报名号等个人信息；名单结论以聚合数据表达。
- 不用局部截图冒充完整样本，不省略分母，不把“出现知名高校”直接推导为“竞争最激烈”。
- 不自动发布，不替用户报名，不上传个人材料。
