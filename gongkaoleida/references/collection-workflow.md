# 公告发现与核验流程

## 1. 浏览器选择

公考雷达可能依赖用户登录态。需要操作公考雷达页面时，使用 `browser:control-in-app-browser` Skill 并遵守其认证与标签页清理规则。

出现登录页、验证码或会话失效时：

1. 不切换到搜索摘要冒充完整扫描；
2. 请用户在当前浏览器完成登录或验证码；
3. 用户回复“好了/继续”后从未完成批次续跑。

## 2. 默认扫描范围

- 地区：广西；
- 时间：北京时间滚动近三天；
- 公告类型：招录公告＋名单/成绩/招录进度线索；
- 分类：公务员、事业单位、教师、医疗、选调、遴选、选调生、三支一扶、大学生村官、基层工作者、银行、国企、公益性岗位、军队文职；
- 当前已验证的全分类入口：`https://www.gongkaoleida.com/area/2290-0-0-2,3,7,8,9,59,60,62,63,66,67,78,80,249-124?page=1`。

如果页面参数或分类发生变化，以可见筛选状态为准，不盲目猜测URL变体。

公考雷达完成后，继续执行 [official-sources.md](official-sources.md) 中的固定官方来源扫描。不能用“公考雷达已经聚合”替代官方来源层。

名单素材使用独立关键词补扫：`资格审查`、`资格复审`、`笔试成绩`、`面试成绩`、`综合成绩`、`总成绩`、`最低合格分数线`、`入围名单`、`面试名单`、`体检`、`考察`、`拟录用`、`拟聘用`、`公示`、`递补`、`补录`。不能只扫描标题含“招聘”的页面。

## 3. 列表层

逐页批量提取公告标题、文章ID、详情URL、列表日期和来源。过滤固定导航、推广入口和跨页置顶的历史公告；按文章URL去重，并将线索先分为`recruitment`和`recruitment_progress`。

继续翻页，直到页面出现早于窗口的公告。保留该页窗口内记录，记录停止位置。不要先按标题关键词、标题人数或单位类型删减。

输出列表审计：页码、原始锚点数、去重公告数、窗口内公告数、停止原因。

名单路线必须同时记录三个不同进度值：`名单候选发现数`、`完成详情/附件分析数`、`剩余未完成数`。发现页翻完只代表候选发现完成，不代表附件分析完成；剩余未完成数不为0时，必须如实写“名单素材分析未完成”。

名单/进度线索不得进入招聘硬筛选后再被当作“非招聘”删除；必须路由至独立名单素材与内部进度队列。

## 4. 详情层

以4—6个标签页为一批并发读取，避免逐条人工点击。每条提取：

- 公考雷达文章时间与来源；
- 正文内官方落款日期；
- 总人数、职位数和报名时间；
- 官方来源锚点；
- “查看相关职位”链接；
- 附件链接和正文关键段落。
- 考试方式、笔试科目、面试方式、体能/技能测试；
- 考试时间地点、成绩构成、考试范围或大纲链接。

正文落款日期、官方页日期与聚合时间冲突时，官方原文日期优先，并记录冲突。

超时处理是详情层的强制步骤：第一次超时后将单页超时提高到120—180秒，把批量缩小到4页并发，至少重试一次。取得正文后继续进入“查看相关职位”，不能停在公告标题和摘要层。

名单/进度公告额外提取：

- 阶段类型：资格审查/资格复审、面试、体检、考察、拟录用/拟聘用、递补/补录、更正；
- 涉及人数和名单附件；
- 资格审查、面试、体检或公示的关键时间；
- 关联原招录公告、原批次、招聘单位和稳定ID；
- 附件总行数、有效行数、重复行和缺失行；
- 成绩、排名、毕业院校、专业、学历、岗位、单位、地区等字段及覆盖率；
- 异议渠道只记录官方期限，不复制个人身份证号、手机号或家庭住址。

完成附件解析后，按 [list-content-rules.md](list-content-rules.md) 评估是否具备数据型视频素材价值。只有流程时间、没有可分析字段或无法确认完整分母的通知只留内部总账。

## 5. 职位表与附件层

标题或正文未给人数、学历、用工性质时，继续读取：

1. 公考雷达职位列表；
2. 单个职位详情；
3. 官方附件Excel/Word/PDF；
4. 官方公众号图片或正文。

线索必须自行核验到终态。执行顺序固定为：正文 → 官方锚点 → 官方站内/域名搜索 → 相关职位 → 单岗详情 → 附件 → 公众号图片。每条记录分开保存三个结果：`verification_result=verified/evidence_failed`、`score_eligibility=score_eligible/not_scored`、`terminal_reason`。全链路都失败时才写`evidence_failed`，并把整轮状态保留为`未完成`；官方已核实但窗口、报名状态、受众、公告性质、必填事实或重复性不通过时，属于`verified + not_scored`，不是核验失败。禁止用`待核/待确认/待补`结束任务，也禁止要求用户替代核验。

考试内容按以下顺序继续查找：公告正文“考试/考核”章节、岗位表备注、考试大纲附件、后续官方笔试或面试通知。若后续通知尚未发布，保留官方原文当下可确认的信息。

只需证明最低学历时，至少找到一个真实岗位并确认是否属于定向人群。示例：“高中起”如果只适用于退役士兵定向岗位，用户表必须写成“高中（退役士兵定向）；普通岗位大专/本科”。

考试字段的固定取值规则：

- 正文明确免笔试：写“免笔试/直接面试”或“直接考核”，不写“无考试”；
- 正文给出科目：保留科目正式名称和类别，如《职业能力倾向测验》A类；
- 正文只写面试但未写形式：写“面试；形式原文未公布”；
- 正文未涉及考试安排：写“原文未公布”；
- 正文明确写“另行通知”：才写“另行通知”；
- 不用往年规则、同类公告或培训机构摘要补齐本次考试科目。

## 6. 官方核验

最终候选必须回到政府、单位官网、官方公众号、人才网等一手来源。公考雷达可以作为发现和结构化线索，不替代官方原文。名单素材必须同时保存官方名单附件；聚合站转述的“最高分、某高校、共X人”等结论不能直接进入用户表。

官方页面打不开但公考雷达明确给出官方链接时，可以把该条留在内部核验队列；不能直接交付。只有确认发布主体可靠、关键事实能由一手内容支持时才能进入用户榜。

内部核验队列不是永久终态。必须继续尝试HTTP/HTTPS切换、上级政府栏目、官方站内搜索、官方域名搜索、人才网主站地市切换、公众号和附件。仍失败则写`取证失败`并判定本轮未完成，不能用“来源打不开”宣布该线索已经处理完。

## 7. 报名状态

按本轮截止时间重新计算：

- 尚未到开始时间：`未开始`；
- 已开始且距截止超过24小时：`报名中`；
- 距截止不超过24小时：`即将截止（24小时内）`；
- 已过截止：`已截止`；
- 无固定截止：`长期招聘/招满即止`。

报名只在工作日、节假日不接待或只接受现场报名时，在报名时间字段中明确写出。

## 8. 来源覆盖表述

- 公考雷达翻完分类和分页：`公考雷达近三天完整扫描`；
- 公考雷达与固定官方来源矩阵全部完成：`核心来源完整扫描`；
- 同时系统覆盖垂直单位、县区站、公众号/工作群和聚合补漏：`本轮完整扫描`；
- 只完成部分来源：`当前已核验下限`。

每轮固定来源覆盖表必须逐项记录`直连完成`或`替代路径完成`、扫描时间、发现数和新增数。公考雷达之外的固定来源没有全部留下完成证据时，不得进入交付完成态。

任何来源缺口都写入内部审计，不用“没有抓到”推断“没有公告”。

## 9. 归属地市标准化

- 用户表第一列固定为`归属地市`，取值优先使用14个设区市名称；
- 县、县级市、城区统一映射到上级地市，例如凌云县写`百色`、龙州县写`崇左`；
- 自治区直属单位按岗位主要工作地点填地市，内部另存`单位层级=区直`；
- 全区统一招考且无法拆分时写`全区`，覆盖多个但非全区时写`多地市`；
- 内部同时保留`归属地市`、`所属区县`和`单位层级`，不得只从标题关键词猜测。
