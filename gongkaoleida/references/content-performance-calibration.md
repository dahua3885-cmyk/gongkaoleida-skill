# 公告内容评分的数据校准

## 1. 当前状态

招聘公告评分的用途是帮助运营决定“这条公告是否值得做、优先发哪个平台”，不是评价岗位客观好坏。现有 V1.0 权重只作为临时先验，尚未经过志公账号真实作品数据校准，不得表述为已经证明的流量模型。

在校准完成前，每条公告分别记录：

- `基础评分`：基于人数、受众、用工性质、单位、报名状态等已核事实生成的临时数字；
- `平台建议`：`抖音优先`、`小红书优先`、`双平台`或`暂不制作`；
- `人工判断依据`：运营为什么愿意或不愿意发布；
- `评分版本`：固定写明，防止不同版本分数混用。

不得用一个未经验证的总分同时代表岗位价值、抖音流量、小红书流量和获客价值。

## 2. 已确认的经验边界

- 人数是重要变量，但必须使用目标受众实际可报人数；人数大不自动等于受众准确。
- 大专和本科通常更接近志公核心受众；高中仅适用于退役士兵等定向岗位时，不得写成广泛低门槛；博士、副高等继续硬排除。
- 编制、控制数、行政编和统一考试属于强信号。
- 辅警、教师、医院等垂直岗位与普通劳务派遣分开判断；去向单位好不能单独把少人数、低待遇的劳务派遣抬到高优先级。
- 小红书和抖音的可发标准不同。同一条公告可能适合小红书快速图文，但不适合抖音视频。
- 时效权重降到5分、招聘规模提高权重，是待数据验证的候选假设，不在样本到齐前写成最终权重。

## 3. 第一轮样本要求

校准分为两条不可混用的证据流：

1. `公告人工等级金标准`：由实际运营者直接给公告标注SS/S/A/B/C，用来学习“运营会选什么”；
2. `平台表现样本`：收集作品数据和线索，用来验证“发出去实际表现如何”。

前者不需等待后台数据就可立即用于相似公告的优先级校准；后者才能用于声称某类公告更可能获得流量或线索。

会议要求先收集：

- 抖音公告型高表现作品至少10条；
- 小红书公告型高表现作品至少10条；
- 每条由实际运营人员在不查看现有模型分数的前提下独立标记“愿不愿发”和主观等级。

只有高表现正样本会产生幸存者偏差。为了真正校准，建议同一账号、相近时间段再补普通或低表现公告作品，每个平台至少10条；如能取得同期公告型全量作品，优先使用全量，不人工挑样本。

## 4. 每条样本字段

```text
样本ID｜平台｜账号｜作品链接｜发布时间｜是否付费｜公告标题｜归属地市｜单位类别｜招聘人数｜目标受众实际可报人数｜最低学历｜编制/用工性质｜官方待遇｜内容形式｜播放/曝光｜点赞｜评论｜分享｜收藏｜私信/加微/线索（如可归因）｜运营盲评｜愿不愿发｜判断理由
```

平台后台没有的指标留空并注明不可得，不能填0。不同平台、账号、付费与自然流量不得直接混算。

## 5. 校准方法

1. 先由运营盲评，不展示现有权重和机器分；
2. 把公告事实标准化为人数、单位类别、用工性质、学历、地区、待遇、时效等特征；
3. 按平台和账号分别比较高、普通、低表现样本；
4. 检查播放、分享、收藏和线索是否给出一致方向，不只看单一播放量；
5. 形成抖音与小红书两套平台适配规则，再决定是否需要两个独立分数；
6. 用未参与定权重的留出样本复测；
7. 只有排序与真实数据、运营选择均达到可接受一致度后，才把新权重从`provisional`改为`validated`。

公告人工金标准与机器分不一致时，必须保留`operator_gold`、`machine_score`、差异方向和原因，不用其中一个覆盖另一个。

每次改权重必须升级评分版本，保存旧权重、样本范围、验证结果和公告分数变化，禁止静默覆盖。
